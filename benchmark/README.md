# Benchmark (Phase F)

Reproducible benchmark for what this project can measure without a GUI.
Every metric is either a number with its sample count or `null` plus a
`reason`. Failures are never fabricated or omitted.

## Run

```sh
make benchmark            # default: benchmark/results, 20 latency iterations
go run ./cmd/bench -out /tmp/bench -iters 5
go run ./cmd/bench -out /tmp/bench -iters 1 -json=false  # summary only
```

The corpus is generated on demand from the repo's own writers
(`internal/ooxml`) into a temp dir; binary fixtures are never committed.
A manifest is recorded at `benchmark/corpus/manifest.json` (and copied next
to the result) with, per fixture: `id`, `filename`, `generator`, `license`
(`MIT (generated by this repository)`), `sha256`, and `suites`. The bench
re-reads the fixtures from disk and verifies the hashes match.

Fixtures: minimal DOCX, DOCX with table and headings, DOCX with a customXml
unknown part (injected into the generated package), XLSX with headers, rows
and a formula, PPTX with 3 slides.

## What each metric means

- `validation.validation_errors`: validator `fail` checks across all
  fixtures (must be 0). `open_without_repair` is true only with zero fails;
  it is a structural proxy, not a real office open.
- `noop_preservation.unrequested_changed_entries`: ZIP entries outside the
  targeted part whose decompressed bytes changed after a content-identical
  rewrite (must be 0). `unrequested_change_rate` = changed untargeted /
  total entries. PPTX is skipped (`no_inplace_pptx_edit`).
- `targeted_change.task_success`: DOCX paragraph text and XLSX cell value
  read back correctly. `formula_preserved`: the XLSX `SUM(C2:C3)` formula
  is still present. `object_preserved`: the unknown `customXml/item1.xml`
  part is byte-identical after an edit elsewhere.
- `conflict_detection.conflict_detection_accuracy`: 200 generated cases
  (100 matching, 100 mismatching digests) through `operations.CheckRevision`.
- `rollback.rollback_success_rate`: prepare→commit→rollback plus
  prepare→rollback over 100 iterations.
  `unknown_outcome_reported_rate`: prepare→unknown receipts flagged
  `UnknownOutcome`.
- `latency`: per operation type, `iters` runs with p50/p95/p99 in
  milliseconds (nearest-rank). `peak_rss_kb` is `runtime.MemStats.Sys`
  (Go heap sys), not OS RSS.
- `security_negative.security_negative_pass_rate`: packages passing
  `go test -run 'TestFS|TestEdit.*Error|TestDecode|TestPlugin' -count=1
  ./internal/...`, with raw passed/failed package counts.
- `crash.panics` / `timeout.timeouts`: panics recovered and >30s overruns
  observed across suites (must be 0).

## Explicitly NOT measured

- Visual preservation (no pixel comparison of rendered documents).
- Perceptual similarity of layouts, fonts, or pagination.
- Real office open (LibreOffice/ONLYOFFICE/desktop editors never launch).
- Desktop editor task success (no GUI automation exists here).

## Machine-specific

Results depend on CPU, RAM, OS, Go version, and installed binaries
(Python, ONLYOFFICE, Document Builder), all recorded in the JSON header.
Only compare results from identical machines and software.
