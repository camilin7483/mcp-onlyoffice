# Benchmark: what `make benchmark` measures

Runnable via `make benchmark` (default: `benchmark/results`, 20 latency
iterations) or directly:

```sh
go run ./cmd/bench -out /tmp/bench -iters 5
go run ./cmd/bench -out /tmp/bench -iters 1 -json=false  # summary only
```

Implementation: `cmd/bench/main.go`. The corpus is generated on demand from
this repo's own writers (`internal/ooxml`) into a temp dir; binary fixtures
are never committed. A manifest (`benchmark/corpus/manifest.json`, copied
next to each result) records per-fixture `id`, `filename`, `generator`,
license (`MIT (generated by this repository)`), `sha256`, and `suites`; the
bench re-reads fixtures from disk and verifies the hashes (`manifest_verified`).
See also `benchmark/README.md`.

## What each metric means

- `validation.validation_errors` — validator `fail` checks across all 5
  fixtures (must be 0). `open_without_repair` is true only with zero fails;
  it is a structural proxy from `internal/validator/validator.go`, **not** a
  real office open.
- `noop_preservation.unrequested_change_rate` — ZIP entries outside the
  targeted part whose decompressed bytes changed after a content-identical
  rewrite, over 4 samples (must be 0). PPTX is skipped
  (`no_inplace_pptx_edit` — no in-place PPTX editor exists in
  `internal/ooxml/edit.go`).
- `targeted_change.task_success` — DOCX paragraph text and XLSX cell value
  read back correctly after an edit. `formula_preserved`: the
  `SUM(C2:C3)` formula survives. `object_preserved`: the unknown
  `customXml/item1.xml` part is byte-identical after an edit elsewhere.
- `conflict_detection.conflict_detection_accuracy` — 200 generated cases
  (100 matching, 100 mismatching digests) through
  `operations.CheckRevision` (`internal/operations/revision.go`).
- `rollback.rollback_success_rate` — prepare→commit→rollback plus
  prepare→rollback over 67 attempts. `unknown_outcome_reported_rate` —
  prepare→unknown receipts flagged `UnknownOutcome` (33 attempts).
- `latency` — per operation type, `iters` runs, p50/p95/p99 in milliseconds
  (nearest-rank). `peak_rss_kb` is `runtime.MemStats.Sys` (Go heap sys),
  not OS RSS.
- `security_negative.security_negative_pass_rate` — packages passing
  `go test -run 'TestFS|TestEdit.*Error|TestDecode|TestPlugin' -count=1
  ./internal/...`, with raw passed/failed package counts.
- `crash.panics` / `timeout.timeouts` — recovered panics and >30 s overruns
  observed across suites (must be 0).

## Environment capture

Every result records `commit`, `date`, `os`/`arch`, `cpu_model`,
`total_ram`, `go_version`, `python_version`, `onlyoffice_version`, and
`builder_version` (null when the binary is absent — the builder backend is
optional, see `docs/backends.md`).

## What is NOT measured and why

- Visual preservation (no pixel comparison of rendered documents).
- Perceptual similarity of layouts, fonts, or pagination.
- Real office open (LibreOffice / ONLYOFFICE / Desktop Editors never launch
  in the bench; `open_without_repair` is structural only).
- Desktop editor task success (no GUI automation exists here).

These need a renderer or a live editor session, neither of which the bench
(`cmd/bench/main.go`) drives.

## How to read results without over-claiming

- Results are machine-specific: only compare runs from identical hardware
  and software (the JSON header exists for exactly this).
- A green run proves the measured properties on the generated corpus; it
  says nothing about arbitrary user documents, visual fidelity, or editor
  behavior.
- Latest run on this machine (`benchmark/results/bench-d77900e-20261119T211009Z.json`,
  12th Gen i3-1215U, Linux amd64, Go 1.27.4, Python 3.14.10, ONLYOFFICE
  9.0.4.50, no builder): validation **0 errors on 5 fixtures**,
  unrequested change rate **0** (4 samples, PPTX skipped), targeted change
  success with formula and unknown-part preservation, conflict detection
  **1.0 on 200 cases**, rollback **1.0 on 67 attempts** (unknown-outcome
  reporting 1.0 on 33 attempts), 0 panics, 0 timeouts.
